## 1. 目标与视觉取舍

将当前产品演示丰富为一个小型工业设计展区：中央 Duo 是唯一主角，左侧解释配件结构，右侧表达材料与配色，底座和地面建立空间层次。

参考图主要落实五项：

1. 暖白低矮圆角底座，具有清晰的厚度、柔和接触阴影及克制的底缘亮线。
2. 暖灰地面、极淡网格、产品周围的柔和 Halo。
3. 左后方零件展示板：外壳、D-Pad、ABXY 与简短标签。
4. 右后方配色 Dock：蓝、暖白、石墨三件外壳样品。
5. 一块产品铭牌和一张原创 `DUO / 01 / GAME CARD` 卡带。

**建议以参考图的固定展板陈列替代首版自由悬浮爆炸图。** 固定陈列有明确支撑关系，文字更易组织，也能减少对 Intro 的视觉干扰。保留轻微离板间距，用阴影解释零件体积。

| 元素 | 本方案建议 | 原因 |
|---|---|---|
| 圆角底座、地面、Halo | 第一阶段主体 | 最直接建立展厅感 |
| 左侧展板、右侧 Dock | 第二阶段主体 | 说明产品结构与配色 |
| 产品铭牌、原创卡带 | 第三阶段补充 | 提供产品身份和 NDS 暗示 |
| 弧形背景墙 | 地面阶段先做灰盒，后续精修 | 收住空间，避免远景黑色背景露出 |
| 墙面 `DUO` 字样 | 最后按留白决定，默认关闭 | 参考图的产品与展板已构成主要信息 |
| 磁吸轨迹、局部标注 | 后续可选增强 | 需明确状态与遮挡逻辑，不阻塞静态布景 |
| 绿植、额外前景样品 | 暂缓 | 首版优先保证左右配件与主体的层级 |
| DOF、Bloom | 暂缓 | 先靠构图、材质与明暗分层；双屏可读性优先 |

## 2. 当前工程事实与设计文档修正

以下为源码核对结果，而非新功能承诺。

| 项目 | 当前事实 | 对本次实施的影响 |
|---|---|---|
| 地面 | `Stage.js` 为 20 × 20 × 0.12 的倒角桌板，Plastic010 贴图 | 已有大面积承影面，需要新增小底座层 |
| 网格 | `ModelInspector.js` 的 `GridHelper(20, 20)`，默认开启，Y = -0.01 | 不是地面材质的一部分；设计稿中的 `gridOpacity = 0.45` 是示意值 |
| 支撑高度 | `ModelAdapter.getStageSurfaceWorldY()` 做模型到世界空间换算 | 不将进度记录中的世界高度当常量 |
| 产品尺度 | `fitModel()` 将 Bind Pose 最大包围盒维度归一到 3.2 | 文档中的米制尺寸不能直接作为运行时世界单位 |
| 产品姿态 | 首帧 8°，Hero / Play 110°；Controller 安装矩阵已保存 | 新布景围绕现有产品姿态布局 |
| 主模型 | `sources.js` 加载 `/iphone.glb`；稳定映射外壳和五个按键 Mesh | 展示件通过 `ModelAdapter` 提供语义引用 |
| 其他 GLB | 磁盘还有 `public/glb/iphoneDuo.glb`、`gameController.glb`，当前未加载 | 未验证其内部结构与当前模型一致性，不作为已可用的拆件来源 |
| 灯光 | 半球光 + 两盏方向光，主光投影；`scene.environment` 未设置 | 沿用现有照明路线调参 |
| 色调映射 | ACES，曝光 1.1 | 暖白材质和亮线在此基线上调色 |
| GTAO | 当前 radius 0.15、thickness 0.40、strength 1.5、32 samples、全分辨率 | 进度文档 3.14 的半分辨率 / 16 samples 是历史记录；性能比较以源码为准 |
| 后处理 | GTAO / Denoise，没有 Bloom 或 DOF | 自发光材质不会自动获得光晕或照亮周边 |
| 输入 | `World` 只将两块产品屏幕传入 `InputRouter` | 静态展示件不应加入交互命中列表 |

PRD 中“未来替换外部展台模型”仍是既有方向。本方案提出先用程序化几何完成地面与小底座分层，接口保留外部几何替换能力；这属于待实施提案，不表示外部资产已经到位。

## 3. 构图与空间坐标

### 3.1 布局基准

采用世界 Y 作为场景竖直方向，在 XZ 平面布置展区；这只约束布景，不改变产品内部铰链或滑轨的局部坐标系。

- 布景中心以 **110°、Controller 安装完成** 的产品投影为基准。
- 定义 `W` 为该姿态的产品横向占地宽度，`D` 为前后占地深度。
- 测量时排除 Helpers 与布景；不要每帧根据动画中的 Controller 更新尺寸，否则地面与底座会跟着运动。
- 灰盒测量应在首帧渲染前的受控流程完成，或基于独立的矩阵计算；若临时改变 Rig，必须保存并恢复姿态、可见性与矩阵，不能触发 Intro 或创建 Timeline。
- 尺寸与偏移使用 `W`、`D` 比例；实际值在 Tweakpane 校准后记录。

### 3.2 Hero 布局初值

当前 Hero 位于世界 +Z 一侧，X 向右；以下仅作为首版灰盒起点。

| 元素 | 布局初值 | 限制 |
|---|---|---|
| 中央底座 | 宽约 1.5W，深约 1.4D，厚约 0.04–0.07W | 以真实承托区域检查中心偏移，不能只按整机 AABB 居中 |
| 底座平面圆角 | 约 0.10–0.16W | 平面大圆角与竖向小倒角分别控制 |
| 地面 Halo | 椭圆半轴约为底座宽、深的 0.65–0.85 倍 | 光环与装配通道、铭牌保持视觉间距 |
| 左展示板 | 中心约 X = -1.0W，Z = -0.35D；板宽约 0.65W | 可轻转向 Hero；板顶优先低于主机上屏顶边 |
| 右配色 Dock | 中心约 X = +1.0W，Z = -0.25D；总宽约 0.65W | 三样件组成一组，整体视觉重量低于左板 |
| 产品铭牌 | 底座前左侧，小幅后倾 | 不遮 Controller 按键，不落入入场扫掠区 |
| 原创卡带 | 地面前右侧，宽约 0.16–0.22W | 只保留一张，弱于铭牌与产品 |

参考图是横向构图，并且视线比当前 Hero 更平。当前 Hero 位置 `(0, 3.5, 5)`、目标 `(0, 0.25, 0)`、FOV 31；只增加道具未必能得到参考图的层次，灰盒阶段需要评估降低 Hero 俯角或略微后退。

建议横屏 Hero 中央产品先以画面宽度约 45%–55% 为构图目标，最终以双屏和按键的识别度决定。Play 仍以清晰游玩为目标，配件允许自然离开画面边缘。

### 3.3 镜头与窄屏

- 同时检查 Folded、Assembly、Hero、Play 及镜头过渡中间态。
- Assembly 是高机位斜视，不能只检查正面 Hero 是否遮挡。
- Hero / Play 的受限 Orbit 当前为方位 ±16°、极角 ±10°、距离 ±10%；检查边界位置而不只检查中心机位。
- 首版窄屏保留产品、底座与 Halo，隐藏左右展示组及卡带；在 `resize()` 中集中切换，不增加逐帧排版。
- 断点先以宽高比 1 为试验值，横屏边界再调；隐藏规则与画幅有关，不随用户拖动镜头闪现。
- 若窄屏仍裁切产品，再由 `CameraDirector` 做尺寸适配，保持单一相机控制入口。

## 4. 地面与底座分层

### 4.1 优先保持产品的世界变换

设 `supportY = product.getStageSurfaceWorldY()`，底座总厚度为 `H`：

```text
产品原有位置与接触余量
──────────────────────────  supportY：小底座顶面
         小底座 H
──────────────────────────  floorY = supportY - H：大地面顶面
         大地面厚度向下延伸
```

小底座顶面沿用当前支撑高度，大地面下移。这样无需为增加底座而抬升 `PresentationRoot`，也无需改动已校准的 Camera Target 或 Controller 安装矩阵。

现有 `Stage` 负责大地面；拟新增底座组件负责中间一层。更改厚度时，底座顶面固定，底面和地面联动。拟提供明确的设置接口，不跨组件直接写私有 Mesh。

### 4.2 几何与材质

- 小底座采用圆角矩形轮廓挤出，平面圆角与竖向倒角独立。现有 `RoundedBoxGeometry` 的半径受最薄边限制，单纯增大 bevel 无法得到参考图那种低矮大圆角平面。
- 顶面使用暖白、非金属 `MeshStandardNodeMaterial`；粗糙度建议从 0.35–0.5 开始试调，微法线明显弱于蓝色 Controller。
- 大地面保留 Plastic010 作为初始表面；小底座先用程序化颜色和微表面，避免为了分层再加载一套大贴图。
- 若后续复用地面纹理，要为不同 repeat 创建独立 Texture 包装并明确释放所有权，不能改同一个共享 Texture 的 repeat。
- 底座投射和接收阴影；地面接收阴影。检查底座底缘黑线，避免 GTAO 与实时投影叠加过重。

### 4.3 网格、Halo 与亮线

建议关闭默认调试 Grid，保留其手动调试开关；视觉网格进入地面的 TSL 材质，与地面共用高度和深度。

- 网格基于世界 XZ 坐标，使用导数抗锯齿与距离淡出；初始混合强度 0.08–0.12，避免掠射闪烁与无穷延伸。
- Halo 由以展区中心为基准的椭圆距离场生成：宽而浅的亮度渐变 + 可独立开关的细环。
- 宽渐变以地面基色混合为主，仍接受阴影；细环可增加低强度自发光。
- 底缘亮线采用窄发光带，地面上的暖色溢光由局部渐变近似。**这不是实时 GI，发光 Mesh 本身不会照亮台面或模型。**
- 默认通过材质整合地面效果，避免多个共面透明 Plane 造成 Z-fighting、排序或 AO 问题。
- 平面坐标、半轴、线宽和强度均由 uniform 控制；TSL 函数放入 `src/shaders/`。

### 4.4 装配通道

必须在完整 Entry → Reveal → Align → Slide → Lock 流程中检查底座、铭牌和配件的碰撞与遮挡。

`ControllerAssembly.applyMotionPose()` 使用 `installedPosition - railAxis × railDistance`。虽然当前配置的轴向为 -Z，入场位置还包含此负号、偏移、弧线和 BottomRig 到世界空间的变换，不能仅凭“-Z”文字在世界空间预留通道。

灰盒阶段采样动画位姿，合并 Controller 世界包围盒形成保守扫掠区域；对疑似与底座交叠的地方再看实际几何。初始设计优先调整底座轮廓、中心及铭牌位置。若确有无法兼容的结构冲突，应记录并讨论底座方案，而不是直接改变安装终点或已校准的装配动作。

## 5. 左侧零件展示板

### 5.1 首版内容与资产边界

当前代码已稳定识别：

- `controllerShell`：完整外壳样件。
- `buttons.dpad`：D-Pad。
- `buttons.a / b / x / y`：四枚按钮帽。

参考图的 `Top Shell / Bottom Shell / Phone Rail Adapter` 尚未作为独立语义节点核实。**首版用一件完整外壳 + D-Pad + 四枚按钮，不把同一外壳的两个副本标成真实上下壳。** 若希望严格还原内部结构，需先检查现有 GLB 是否可独立提取；不足时由用户补充独立配件资产。

板面建议采用外壳在左、D-Pad 和 ABXY 分区在右的排版，保留未来增加滑轨区域的空间。

### 5.2 展板外观与文字

- 首版用微磨砂浅色背板、柔和边缘高光和实体底脚实现参考图的轻盈感。
- 透明亚克力属于后续材质试验：当前 AO 预通道排除透明对象；真实 transmission 还需核实额外渲染开销及在现有管线中的效果。
- 标签首版使用 `Controller Shell`、`D-Pad`、`Button Caps`、`3D Printed`。
- `PLA / PETG / PA12 / TPU` 与具体原型编号只有在用户确认后才填写，参考图上的材质文字不作为产品事实。
- 使用局部 CanvasTexture 铭牌，字体栈采用系统无衬线；标签统一合图或少量纹理，仅在内容变化时上传。
- 文字遵循物理表面照明和正确 sRGB 配置，避免无照明白底贴片突兀发亮。

### 5.3 克隆、坐标与材质所有权

- 通过 `ModelAdapter` 拟新增的公开方法取得展示件源信息，节点名继续集中管理。
- 在按键未受输入影响的静止基线捕获相对矩阵；展示副本挂独立 Scene 子树，不能随 Intro 隐藏、装配或按压。
- 克隆时考虑 GLB 父层变换，不能只复制 Mesh 的 local position 就假定方向正确；优先保留适当的变换包装层，避免有非均匀缩放时错误分解出剪切。
- 可共享只读 Geometry；展示材质、颜色 uniform 与调参状态独立。不要对共享 Geometry 执行 `applyMatrix4()` 来摆放副本。
- 当前 `ControllerShellMaterial` 用 `colorNode` 和 uniform 控制颜色；普通 `material.color.set()` 不足以生成独立配色，NodeMaterial 浅复制也不能视为 uniform 已独立。
- 建议复用 `controllerPlastic.js` 的噪声与法线函数，抽取可生成独立 uniform 的材质构造逻辑，避免给每个样件创建完整产品调试组件。
- 首版展示样件不绑定主机安装态 EXR，使用实时灯光与 GTAO。主机现有 Lightmap 保持原用途；重定向后的样件若需要烘焙，应单独评估。

## 6. 右侧配色 Dock 与补充道具

### 6.1 配色 Dock

一座低矮暖白 Dock，三件缩小外壳样品轻微错开：蓝色、暖白、石墨。样品不是另外三台完整设备，不包含运行屏幕、输入或 Controller 装配逻辑。

- 第一版共享外壳几何，使用三组独立颜色参数；蓝色先取当前主机材质色 `#3e5f7c` 为起点。
- 同组样件保持一致尺寸、粗糙度与摆放节奏，以颜色作为主要差别。
- Dock 前方一条 `Color Studies` 标签与三枚色点即可。
- 先用普通 Mesh 做数量和阴影预算；三件样品无需提前引入实例化材质系统。

### 6.2 产品铭牌与卡带

- 产品牌：`iPhone Duo`、`3D Printed Controller`，可补一行 `Game Changer`；宽度约 0.22–0.30W。
- 卡带：程序化倒角壳、插槽细节、原创 `DUO / 01 / GAME CARD` 标签，宽度参考第 3 节。
- 标签是少量静态纹理，不接入模拟器帧；不使用参考图像素裁切作为几何、材质或游戏内容。
- 两者位置均需通过装配扫掠和屏幕遮挡检查。

## 7. 背景与照明

- 暖灰地面向远处弧形墙连续过渡；优先用连续剖面生成几何并保证弧面法线平滑，拼接处不能出现硬折线、缝隙或重叠面。
- 远景墙放在左右展品之后，覆盖四组镜头以及受限 Orbit 的可见背景；墙体不进入产品 fit 包围盒。
- 墙面色、地面色与 `scene.background` 协调为暖灰白；当前深色背景 `#090d14` 需在此阶段随环境一起调整。
- 沿用现有三灯、ACES 与主机 EXR；优先微调冷色补光比例，保持蓝壳与暖白环境的区分。
- 新展品超出主光阴影范围时，按展区包围盒重新校准 shadow target / 正交范围及 near/far。当前参数以原点为 target，若改变 target 必须同步修正距离推导。
- 不一开始提高阴影分辨率或叠加投影灯；先检查 2048² 覆盖范围与细节之间的平衡。
- 展示板、Dock 与底座应有接触阴影，墙面避免因 GTAO thickness 偏大出现宽黑晕。

## 8. 模块与生命周期方案

以下为拟新增/调整的职责，不代表文件已存在。

```text
World
├─ Environment                  现有：灯光、背景、阴影参数
├─ ModelAdapter                 现有：产品、语义节点；补充只读展示源接口
├─ Stage                        现有：大地面、网格与 Halo 材质
└─ Exhibition                   拟新增：布景布局、尺寸、模式/画幅策略
   ├─ ProductPlinth             中央小底座及底缘亮线
   ├─ PartsDisplay              左侧零件板及标签
   ├─ ColorDock                 右侧配色样件
   ├─ ExhibitProps              小铭牌与原创卡带
   └─ Cyclorama                 弧形背景

src/shaders/exhibitionFloor.js  拟新增：网格、径向渐变、细环
```

- 按阶段创建真实需要的组件，不提前创建空模块；静态对象无需空 `update()`。
- `World` 在产品初始化后传入支撑高度、尺寸及展示源；布局协调通过显式接口更新 Stage 的地面高度。
- 当前 `Experience.resize()` 只通知 Camera / Renderer，`World` 尚无 resize 方法；实施时补齐 `Experience → World → Exhibition` 的显式 resize 调用，并在布景构造完成后应用一次初始画幅策略。
- 展示模式首版靠机位与画幅分层，不增加新的产品状态；可选标注后续再监听既有 `intro:state` / `product:mode`。
- 新增加载型资源只在 `sources.js` 声明；程序生成 Geometry / CanvasTexture 由组件持有。
- 销毁顺序为先展示组件、后产品，释放自有几何、材质、CanvasTexture、Tweakpane folder 与事件监听；共享产品 Geometry 仍由 `ModelAdapter` 最终释放。
- 如后续增加显隐 Timeline，Replay / Skip / Continue / destroy 必须有同步收束路径。

### 建议 Tweakpane 控件

| 分组 | 控件 |
|---|---|
| Exhibition | 总开关、左右展组开关、窄屏策略 |
| Plinth | 宽深比例、厚度、平面圆角、竖向倒角、XZ 偏移、颜色、粗糙度 |
| Floor | 地面色、网格强度/间距/淡出、Halo 中心/半轴/宽度/强度、细环开关 |
| Parts / Dock | 位置、朝向、比例、组内间距、颜色 |
| Props | 铭牌与卡带开关、位置、角度 |
| Cyclorama | 距离、宽度、弧半径、颜色 |

高度与共享布局约束由组件方法处理，不能让各控件独立写出互相矛盾的 Y 坐标。首版不承诺任意产品旋转后自动重排整个展厅，产品展示变换调整后应显式重新校准布局。

## 9. 分阶段交付与验收

### S1 — 基础空间与全流程灰盒

交付：小底座、大地面分层、弱网格、Halo、弧墙灰盒、左右展组包围体，以及可复现的布局参数。

验收：

- 8° 首帧、展开、装配、110° Hero 均无新增穿插；Controller 全路径留空。
- 产品位置、折叠轴和安装终点与原有基线一致；底座高度变化不会抬升产品。
- 四个机位和 Orbit 边界无明显裁切/遮挡，背景不会意外露黑或切入镜头。
- 网格服从地面高度，无浮线、闪烁；Halo 仍能看见物体投影。
- 横屏与窄屏形成可接受构图，记录 Hero 是否需要微调。

### S2 — 左右工业设计展示

交付：真实外壳 / 按键展示副本、左侧标签板、三配色 Dock；以实际已有零件作为首版资产范围。

验收：

- 主机与展示件颜色独立，调样件不改变主机；副本不响应游戏按键或 Intro 装配。
- 左侧零件可以区分，右侧三样件可读，但主机仍是最高视觉优先级。
- 无来自错误 Lightmap、透明排序或法线方向的明显斑块。
- Replay、Skip、Continue、返回与窗口 resize 后布局稳定。
- 标签不虚构材料与独立结构，窄屏按策略隐藏附属展组。

### S3 — 叙事道具与环境精修

交付：产品铭牌、一张原创卡带、最终背景材质、灯光与阴影校准。

验收：

- 铭牌和卡带有体积与接触感，无遮挡主屏/按键且避开装配区域。
- 环境暖白但保留高光细节，亮线不抢屏幕，蓝壳与白键有清晰层次。
- 背景弧面无接缝，边缘无明显 AO 黑边；双屏内容仍清晰。

### S4 — 可选动态说明

在 S1–S3 完成后评估磁吸轨迹、空间标注、墙面字样、透明亚克力和轻量后处理。每项单独判断视觉收益与性能代价。

磁吸轨迹若实施：方向复用装配坐标计算，阶段变化通过明确回调或事件暴露；当前 `ControllerAssembly.setState()` 只更新参数/面板，并没有现成的装配阶段事件。Lock 后淡出，Playing 隐藏；中断时清理 Timeline。

## 10. 性能与验证方法

1. 运行时实施后执行 `npm run build`、`git diff --check`；WebGPU chunk 超过 500 kB 的现有警告不视为构建失败。
2. 在支持 WebGPU 的最新版浏览器中验证真实 GPU 编译、纹理、阴影和透明材质；构建成功不能代替视觉验收。
3. 改动前后保持相同设备、窗口、DPR、镜头、GTAO 与 NDS 游戏状态，记录帧时间、draw calls、三角形、纹理/几何数量。
4. 分别测量 Hero 静态、Intro 装配与 NDS Playing；以布景开关做同场景 A/B，记录稳定区间及高分位帧时间，避免只比较平均 FPS。
5. 提议将新增布景稳定帧时间增幅控制在基线 15% 内，且不破坏现有游玩体验；这是待设备实测的目标，不是当前性能结论。
6. 优先复用几何、合并标签、减少透明面和投影数量；首次实现不增加大尺寸烘焙图或常驻动画循环。
7. HMR / destroy 后验证新增监听和自有 GPU 资源已释放，共享几何未提前销毁；CanvasTexture 仅内容变化时更新。
8. 功能回归包括：首帧、完整 Intro、Replay、Skip、Continue、Escape、失焦暂停、屏幕点击/触控、键盘/Gamepad 与受限 Orbit。

本轮仅编写方案，尚未执行场景代码改造、GPU 检查或上述性能测量。

## 11. 实施前的未决项与默认推进方式

| 未决项 | 默认推进方式 | 何时需要用户决定 |
|---|---|---|
| 是否严格还原参考图上下壳与滑轨 | 用已确认的完整壳体和按键搭建 S2 | 需要真实拆解结构时补资产或确认可提取节点 |
| 左展板是否必须真实透明 | 首版微磨砂浅色板 | S2 看构图后决定是否做 transmission 试验 |
| Hero 是否改变俯角/距离 | 保留原参数作对照，灰盒提出新参数 | S1 浏览器视觉验收 |
| 打印材料与原型编号 | 仅写 `3D Printed` | 确认实际材料后补标签 |
| 墙面字样、磁吸轨迹、景深 | 默认关闭，进入 S4 再评估 | 静态展厅构图完成后 |

下一步建议从 **S1 基础空间与全流程灰盒** 开始，先验证展台和装配路径兼容，再投入左右展品的材质和标签细节。
